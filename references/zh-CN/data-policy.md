# 数据政策

> 英文辅助版本见 [../data-policy.md](../data-policy.md)。

Jinhua 只记录脱敏后的方法论证据，不保存用户记忆、项目记忆或聊天记录。

## 写入门

一条经验必须能同时写成：

- 可复用的 `trigger`：未来什么时候使用；
- 可复用的 `action`：遇到时具体怎么做。

同时至少满足一项：

- 用户纠正了工作流、推理方向、验证标准、Skill/工具选择或遗漏流程；
- 同一方法在当前项目重复出现；
- 已修复失败暴露出可迁移原因；
- 成功路径暴露出可复用方法；
- 用户明确要求沉淀。

如果离开当前任务的私人细节后无法写清 `trigger + action`，就跳过。

## 可以记录

- 脱敏后的摘要和上下文；
- operator id 和本地 `cluster_key`；
- 来源类型和强度；
- 触发条件、方法动作、迁移条件、反例、验证路径和风险；
- 提案目标、带标题的完整 Markdown 修改块、风险、落点和证据 ID；
- 用户确认结果；
- 实际修改目标和已经验证的修改摘要；
- 项目身份哈希；
- 压缩后的跨项目证据。

## 不能记录

- 完整用户输入或完整对话；
- 姓名、联系方式、账户、凭证、密钥或 token；
- 客户名称、公司秘密或敏感项目标识；
- 私人偏好；
- 一次性普通 bug 事实；
- 全局层中的原始项目路径；
- 全局层中的明文显式项目 ID。

无法安全脱敏时，不要记录。

## 本地与全局边界

项目本地 `.jinhua/data/` 可以保存较完整的信号卡和证据 ID。

个人全局层 `global-data/` 只能保存：

- 哈希化项目身份；
- 精确方法指纹和可读方法键；
- 脱敏摘要与上下文；
- operator、来源类型和强度；
- 已提供的方法卡字段；
- 证据 ID 和聚合计数。

不要把本地原始证据复制到全局记录。使用 `--project-id` 或 `JINHUA_PROJECT_ID` 时，明文只用于生成哈希，全局层只保存哈希和身份来源。

## Hook 边界

Hook 只能写 `.jinhua/runtime/invocation-guard.json`，用途限于本地分类辅助、不同用户回合计数、周期票据和同轮去重。

Hook 不能：

- 迁移核心数据；
- 追加 `signals.jsonl`；
- 创建或更新提案；
- 记录采纳或拒绝；
- 修改 Skill 或项目规则。

## 保留策略

Jinhua 2.0 永久保留已经写入的信号，不再提供压缩删除或忽略状态。弱信号和不安全内容应在写入前跳过，而不是先写入再删除。

## 采纳边界

Agent 先用宿主原生工具修改并验证用户批准的目标。`apply-proposal` 和 `global-apply` 只记录已经完成的采纳。修改或验证失败时，不能写采纳记录。

如果持久化失败，要明确说明账本没有更新，不能声称信号、提案或采纳已经保存。
